# Соглашение о формате данных

## 1. Общий принцип

Блокчейн-реестр хранит **только то, что нужно для верификации**: хэши, статусы, идентификаторы. Всё остальное — персональные данные, PDF, ключи, токены — живёт вне реестра.

---

## 2. Структура блока

Блокчейн — **собственный**, реализованный на Node.js. Формат блока и транзакций определён ниже. Каждая транзакция вызывает один из редьюсеров состояния (`issue`, `revoke`, `addIssuer`, `removeIssuer`), который может породить событие для off-chain индексатора.

### 2.1. Формат блока

```
{
  "height": 42,
  "prevHash": "0x…",
  "timestamp": 1751232000,
  "txs": [ /* массив транзакций */ ],
  "validator": "0x…",
  "signature": "0x…"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `height` | number | порядковый номер блока, начиная с 0 (genesis) |
| `prevHash` | string (hex) | SHA-256 предыдущего блока |
| `timestamp` | number | Unix-время создания блока, секунды |
| `txs` | array | список транзакций в блоке |
| `validator` | string (hex) | адрес валидатора, подписавшего блок |
| `signature` | string (hex) | Ed25519-подпись заголовка блока |

**Хеш блока** — SHA-256 от канонической сериализации заголовка `{ height, prevHash, timestamp, txs, validator }`. Именно он попадает в поле `prevHash` следующего блока.

### 2.2. Формат транзакции

```
{
  "type": "issue" | "revoke" | "addIssuer" | "removeIssuer",
  "payload": { /* поля, зависят от типа */ },
  "nonce": 17,
  "publicKey": "0x…",
  "signature": "0x…"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `type` | string | тип операции |
| `payload` | object | данные операции (см. §2.3) |
| `nonce` | number | счётчик транзакций отправителя (защита от replay) |
| `publicKey` | string (hex) | публичный ключ отправителя |
| `signature` | string (hex) | Ed25519-подпись канонической сериализации `{ type, payload, nonce }` |

### 2.3. Что хранится в состоянии реестра

Состояние — это набор `Map`, которые редьюсеры обновляют при применении транзакций.

**Запись о документе** (`state.diplomas[diplomaId]`):

| Поле | Тип | Описание |
|---|---|---|
| `documentHash` | string (hex) | SHA-256 от PDF + соль |
| `issuer` | string (hex) | адрес вуза-эмитента |
| `issueDate` | number | Unix-время выпуска, секунды |
| `status` | string | `"Valid"` или `"Revoked"` |
| `fileKey` | string | ключ объекта в S3 |
| `docType` | string | `"diploma"` или `"certificate"` |
| `specialtyHash` | string (hex) | SHA-256 от названия специальности |

**Запись о вузе** (`state.issuers[address]`):

| Поле | Тип | Описание |
|---|---|---|
| `did` | string | идентификатор вуза |
| `active` | boolean | аккредитован ли вуз |
| `addedAt` | number | Unix-время аккредитации, секунды |

Это минимум, необходимый для редьюсера `verify`.

### 2.4. Что остаётся вне реестра

| Данные | Где хранится |
|---|---|
| ФИО, специальность (текст), номер документа | off-chain БД |
| PDF-файл | S3 |
| Соль для хэша | off-chain БД |
| Ключ шифрования PDF | off-chain БД |
| Токены доступа к PDF | off-chain БД |
| Причина отзыва (текст) | off-chain БД |
| Журнал аудита | off-chain БД |

**Правило:** персональные данные никогда не попадают в реестр.

## 3. События

События эмитятся редьюсерами при применении транзакций и складываются в журнал блока. Off-chain модуль читает события и строит индекс для быстрого поиска.

### 3.1. `DiplomaIssued`

Эмитится редьюсером `issue`.

| Поле | Тип | Для поиска | Описание |
|---|---|---|---|
| `diplomaId` | string (hex) | да | уникальный ID документа |
| `issuer` | string (hex) | да | адрес вуза |
| `documentHash` | string (hex) | нет | хэш PDF + соль |
| `fileKey` | string | нет | ключ объекта в S3 |
| `docType` | string | нет | `"diploma"` или `"certificate"` |
| `specialtyHash` | string (hex) | нет | хэш специальности |
| `issueDate` | number | нет | Unix-время выпуска |

### 3.2. `DiplomaRevoked`

Эмитится редьюсером `revoke`.

| Поле | Тип | Для поиска | Описание |
|---|---|---|---|
| `diplomaId` | string (hex) | да | ID документа |
| `issuer` | string (hex) | да | адрес вуза |
| `reasonHash` | string (hex) | нет | SHA-256 от текста причины |
| `revokeDate` | number | нет | Unix-время отзыва |

### 3.3. `IssuerAdded`

Эмитится редьюсером `addIssuer`.

| Поле | Тип | Для поиска | Описание |
|---|---|---|---|
| `issuer` | string (hex) | да | адрес вуза |
| `did` | string | нет | идентификатор вуза |
| `timestamp` | number | нет | Unix-время аккредитации |

### 3.4. `IssuerRemoved`

Эмитится редьюсером `removeIssuer`.

| Поле | Тип | Для поиска | Описание |
|---|---|---|---|
| `issuer` | string (hex) | да | адрес вуза |
| `timestamp` | number | нет | Unix-время деактивации |

## 4. Формат передачи данных между модулями

### 4.1. Frontend → Backend

**Формат:** HTTP + JSON.

**Запрос на выпуск документа:**

```json
{
  "version": "1.0",
  "docType": "diploma",
  "holderFullName": "Иванов Иван Иванович",
  "specialty": "Прикладная информатика",
  "issueDate": "2025-06-30",
  "documentNumber": "123456",
  "pdfBase64": "JVBERi0xLjQK..."
}
```

**Ответ:**

```json
{
  "version": "1.0",
  "diplomaId": "0x111...",
  "fileKey": "diplomas/2025/abc.pdf",
  "txHash": "0xabc...",
  "qrUrl": "https://app/verify/0x111...",
  "status": "issued"
}
```

**Правила:**
- даты — ISO 8601;
- идентификаторы — строки;
- ошибки — единый формат `{ error: { code, message } }`.

### 4.2. Backend → Blockchain Node

**Формат:** HTTP + JSON.

Backend формирует транзакцию, подписывает её ключом эмитента и отправляет в блокчейн-ноду:

```
POST /tx
```

```json
{
  "type": "issue",
  "payload": {
    "diplomaId": "0x111...",
    "documentHash": "0x222...",
    "fileKey": "diplomas/2025/abc.pdf",
    "docType": "diploma",
    "specialtyHash": "0x333...",
    "issueDate": 1751232000
  },
  "nonce": 17,
  "publicKey": "0x...",
  "signature": "0x..."
}
```

Нода валидирует подпись, добавляет транзакцию в мемпул и возвращает `txHash`. После формирования блока валидатором транзакция применяется к состоянию, и backend может прочитать результат через:

```
GET /state/diploma/:diplomaId
GET /blocks/:height
```

### 4.3. Backend → Off-chain хранилище

**Формат:** ключ объекта в S3.

```json
{ "fileKey": "diplomas/2025/abc.pdf" }
```

`fileKey` — единственная связь между реестром и файлом.

### 4.4. Backend → База данных

Конкретная СУБД не зафиксирована. Важно на уровне соглашения:

- ПДн хранятся только здесь;
- `diplomaId` — ключ связи с реестром;
- `txHash` — ссылка на транзакцию;
- соль и ключ шифрования — только здесь.

**Сущности:**

| Сущность | Что хранит |
|---|---|
| Пользователь | email, хэш пароля, роль, статус |
| Вуз | название, ИНН, DID, статус |
| Документ | `diplomaId`, ФИО, специальность, номер, дата, `txHash` |
| Файл | `fileKey`, ключ шифрования, соль, IV |
| Доступ | токен, email, срок действия |
| Аудит | кто, что, когда, IP, `txHash` |
