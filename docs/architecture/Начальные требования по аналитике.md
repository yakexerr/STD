# Начальные требования по аналитике

**Версия:** 0.1 | **Дата:** 24.09.2026 | **Связанные документы:** ФТ, Описание формата

---

## 1. Что собираем

Аналитика строится на том, что уже есть в системе (не заводим новых сущностей):

- **Журнал аудита** (`AuditLog`) — входы/выходы, действия пользователей
- **События смарт-контрактов** (`DiplomaRegistry`, `IssuerRegistry`) — выпуски, отзывы, аккредитации
- **Off-chain БД** — документы, доступы, пользователи

Каждое действие логируем как событие: `eventType` (что произошло), `actorId` (кто сделал), `entityId` (над чем), `timestamp`, `txHash` (если есть транзакция).

**Основные типы событий:**
- `auth.login` / `auth.login_failed` — входы
- `diploma.issued` / `diploma.revoked` — выпуски и отзывы
- `diploma.verify_request` / `diploma.verify_result` — проверки документов
- `access.granted` / `access.expired` — выданные доступы
- `issuer.added` / `user.role_changed` — админские действия

Персональные данные в события не попадают (только ID и хэши).

---

## 2. Какие метрики нужны

**Для администратора и аудитора:**
- Количество выпущенных/отозванных документов по периодам
- Сколько проверок сделано, какие результаты (подлинный / отозван / не найден)
- Количество активных вузов
- Неудачные попытки входа (антифрод)
- Проверки отозванных документов (сигнал о возможных попытках использования недействительных дипломов)

**Для вуза-эмитента:**
- Сколько своих документов выпустил/отозвал
- Сколько раз проверили документы этого вуза
- Ошибки в пакетных операциях (CSV)

**Для верификатора:**
- Сколько проверок сделал
- Результаты проверок

**Для выпускника:**
- Список своих документов по статусам
- Сколько раз проверили документы

---

## 3. Дашборды по ролям

**Администратор/Аудитор:**
- Графики: динамика выпусков/отзывов, результаты верификаций
- Таблицы: топ вузов по выпускам, сигналы безопасности (много проверок отозванных/несуществующих документов)
- Фильтры по периодам, вузам, типам документов

**Вуз-эмитент:**
- Своя статистика: выпуски, отзывы, проверки
- Лента последних событий по своим документам

**Верификатор:**
- История своих проверок с результатами

**Выпускник:**
- Список документов со статусами
- Кто и когда проверял документы

**Отчёты:** экспорт в CSV для всех таблиц и журналов.

---

## 4. Хранение и защита

- Всё в off-chain БД (в блокчейн не пишем)
- Дашборды показывают только агрегаты и ID, не персональные данные
- Журнал аудита (уже есть в ФТ) расширим полями для аналитики

---

## 5. Критерии приёмки

- Документ согласован командой
- Схема событий привязана к существующим источникам (AuditLog + события контрактов)
- Определены метрики и дашборды по ролям
- План реализации: начинаем во втором спринте
