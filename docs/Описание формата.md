# Соглашение о формате данных

## 1. Общий принцип

Блокчейн хранит **только то, что нужно для верификации**: хэши, статусы, идентификаторы. Всё остальное — персональные данные, PDF, ключи, токены — живёт вне блокчейна.
---

## 2. Структура блока

Блок — стандартный блок выбранной EVM-сети. Внутри него лежат транзакции, которые вызывают функции наших контрактов. Каждая транзакция порождает событие с фиксированным набором полей.

### 2.1. Что хранится в state контракта

**Запись о документе:**

| Поле | Тип | Описание |
|---|---|---|
| `documentHash` | bytes32 | хэш PDF + соль |
| `issuer` | address | адрес вуза-эмитента |
| `issueDate` | uint64 | дата выпуска (Unix timestamp) |
| `status` | uint8 | `0` — Valid, `1` — Revoked |
| `cid` | string | ссылка на зашифрованный PDF |

**Запись о вузе:**

| Поле | Тип | Описание |
|---|---|---|
| `did` | string | идентификатор вуза |
| `active` | bool | аккредитован ли вуз |
| `addedAt` | uint64 | дата аккредитации |

Это минимум, необходимый для функции `verifyDiploma`.

### 2.2. Что остаётся вне блока

| Данные | Где хранится |
|---|---|
| ФИО, специальность, номер документа | off-chain БД |
| PDF-файл | IPFS/S3 |
| Соль для хэша | off-chain БД |
| Ключ шифрования PDF | off-chain БД |
| Токены доступа к PDF | off-chain БД |
| Причина отзыва (текст) | off-chain БД |
| Журнал аудита | off-chain БД |
| `diplomaId`, `docType`, `specialtyHash` | только в событиях |

**Правило:** персональные данные никогда не попадают в блокчейн.

---

## 3. События

События — основной канал истории. Off-chain модуль слушает их и строит индекс.

### 3.1. `DiplomaIssued`

Эмитится при выпуске документа.

| Поле | Тип | Индексируется | Описание |
|---|---|---|---|
| `diplomaId` | bytes32 | да | уникальный ID документа |
| `issuer` | address | да | адрес вуза |
| `documentHash` | bytes32 | нет | хэш PDF + соль |
| `cid` | string | нет | ссылка на PDF |
| `docType` | uint8 | нет | `0` — диплом, `1` — сертификат |
| `specialtyHash` | bytes32 | нет | хэш специальности |
| `issueDate` | uint64 | нет | дата выпуска |

### 3.2. `DiplomaRevoked`

Эмитится при отзыве документа.

| Поле | Тип | Индексируется | Описание |
|---|---|---|---|
| `diplomaId` | bytes32 | да | ID документа |
| `issuer` | address | да | адрес вуза |
| `reasonHash` | bytes32 | нет | хэш причины отзыва |
| `revokeDate` | uint64 | нет | дата отзыва |

### 3.3. `IssuerAdded`

Эмитится при аккредитации вуза.

| Поле | Тип | Индексируется | Описание |
|---|---|---|---|
| `issuer` | address | да | адрес вуза |
| `did` | string | нет | идентификатор вуза |
| `timestamp` | uint64 | нет | дата аккредитации |

### 3.4. `IssuerRemoved`

Эмитится при деактивации вуза.

| Поле | Тип | Индексируется | Описание |
|---|---|---|---|
| `issuer` | address | да | адрес вуза |
| `timestamp` | uint64 | нет | дата деактивации |

## 4. Формат передачи данных между модулями

### 4.1. Frontend → Backend

**Формат:** HTTP + JSON.

**Запрос на выпуск документа:**

```json
{
  "version": "1.0",
  "docType": "diploma",
  "holderFullName": "Иванов Иван Иванович",
  "specialty": "Прикладная информатика",
  "issueDate": "2025-06-30",
  "documentNumber": "123456",
  "pdfBase64": "JVBERi0xLjQK..."
}
```

**Ответ:**

```json
{
  "version": "1.0",
  "diplomaId": "0x111...",
  "cid": "bafybei...",
  "txHash": "0xabc...",
  "qrUrl": "https://app/verify/0x111...",
  "status": "issued"
}
```

**Правила:**
- даты — ISO 8601;
- идентификаторы — строки;
- ошибки — единый формат `{ error: { code, message } }`.

### 4.2. Backend → Blockchain

**Формат:** вызов функции контракта через ethers.js.

Что уходит в `issueDiploma`:

| Аргумент | Тип | Пример |
|---|---|---|
| `diplomaId` | bytes32 | `0x111...` |
| `documentHash` | bytes32 | `0x222...` |
| `cid` | string | `bafybei...` |
| `docType` | uint8 | `0` |
| `specialtyHash` | bytes32 | `0x333...` |
| `issueDate` | uint64 | `1751232000` |

Backend получает обратно `txHash` и слушает событие `DiplomaIssued`.

### 4.3. Backend → Off-chain хранилище

**Формат:** CID-строка.

```json
{ "cid": "bafybeigdyrzt5sfp7udm7hu76uh7y26nf3efuylqabfoclgtqy55fbzdi" }
```

CID — единственная связь между блокчейном и файлом.

### 4.4. Backend → База данных

Конкретная СУБД не зафиксирована. Важно на уровне соглашения:

- ПДн хранятся только здесь;
- `diplomaId` — ключ связи с блокчейном;
- `txHash` — ссылка на транзакцию;
- соль и ключ шифрования — только здесь.

**Сущности:**

| Сущность | Что хранит |
|---|---|
| Пользователь | email, хэш пароля, роль, статус |
| Вуз | название, ИНН, DID, статус |
| Документ | `diplomaId`, ФИО, специальность, номер, дата, `txHash` |
| Файл | `cid`, ключ, соль, IV |
| Доступ | токен, email, срок действия |
| Аудит | кто, что, когда, IP, `txHash` |
