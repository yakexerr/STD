# 0001. Выбор технологического стека для клиентской части (Frontend)

* **Статус:** Принято
* **Дата:** 2026-09-17

## Контекст и постановка проблемы
Для системы верификации дипломов необходим интерфейс личных кабинетов с поддержкой динамических форм, клиентской валидации и хэширования файлов (SHA-256).

Команда владеет тремя основными языками разработки: **JavaScript, Python и C#**. Необходимо выбрать подход для реализации клиентской части.

## Рассмотренные альтернативы
1. **Python (Django):**
   * *Плюсы:* Высокая скорость разработки серверного рендеринга.
   * *Минусы:* Классический серверный рендеринг (SSR) через шаблоны Jinja/Django плохо подходит для построения интерактивного Single Page Application (SPA); усложняется клиентское хэширование больших файлов (SHA-256) в браузере до их отправки на сервер; нарушается разделение на независимый клиент и REST API.
2. **C# (.NET Blazor WebAssembly):**
   * *Плюсы:* Строгая типизация C#, компонентная модель.
   * *Минусы:* Отсутствие у команды практического опыта разработки UI на Blazor. Blazor WebAssembly существенно утяжеляет начальную загрузку приложения (требуется скачивание рантайма .NET в браузер); экосистема библиотек для работы с Canvas/QR-кодами и криптографией в браузере уступает экосистеме npm
3. **JavaScript (React + Vite):**
   * *Плюсы:* Нативный для браузера язык (JS); реактивная компонентная архитектура React для интерактивных форм; Vite как легковесный инструмент быстрой сборки dev-сервера; единый язык (JS/Node.js) для всего проекта; интеграция с ESLint.
   * *Минусы:* Необходимость отдельной настройки клиентского роутинга (`react-router-dom`).

## Решение
Использовать для клиентской части язык **JavaScript** и связку **React + Vite** с поддержкой **ESLint** (директория `frontend/`).

## Ожидаемые последствия и компромиссы
* **Положительные:** 
  * Единый стек разработки (JavaScript на клиенте и Node.js на бэкенде/ядре).
  * Быстрый отклик интерфейса без перезагрузок страниц при проверке и выпуске дипломов.
  * Автоматический контроль стандартов кода и стиля через ESLint в соответствии с правилами разработки (`CONTRIBUTING.md`).
* **Компромиссы (с чем придется работать):** 
  * Необходимость самостоятельно конфигурировать клиентскую маршрутизацию и управлять состоянием авторизации (JWT) на фронтенде.
